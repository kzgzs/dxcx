# 营销示例数据说明

为 7 个营销模块（拼团、幸运拼团、砍价、秒杀、团购、周期购、服务预约）各准备 **2 个平台自营 + 2 个商户**示例商品，让后台「营销/扩展」与「客户端 → 商户」菜单打开即有参考数据，避免空白。

## 数据口径（照点大 canzhao，非手写假数据）

- 平台自营商品 `bid=0`；商户商品 `bid=商户ID`、`ischecked=1`（`business_sysset.product_check=0` 为免审）。
- 全部经各模块 Service 的商品保存入口真实落库（规格子表、价格汇总、活动时间完整）。
- 没有正常商户时（如全新部署），会自动创建一个名为 **「示例商户·优选生活馆」** 的演示商户承接商户商品；已有正常商户则直接复用第一个。
- 商品名统一以 **「【示例】」** 开头；图片在 `public/uploads/demo/`（随 Git 仓库提交，线上无需 GD 也能显示）。

## 部署时自动生成（无需手动跑命令）

数据库迁移 `20260919100001_seed_demo_products` 会在部署迁移时**幂等**生成：

```bash
php think migrate:run    # 建表 + 初始数据（已包含本示例商品），可重复执行，已存在则跳过
php think seed:run       # 超管账号 / 平台配置等 Seeder（按需，幂等）
```

因此线上只要正常执行 `migrate:run`，7 个商品页就会有示例数据，不会出现“忘记导入”的情况。逻辑与 `demo:products` 命令共用 `app\common\service\DemoProductGenerator`，只有一份实现。

## 手动操作

```bash
php think demo:products            # 生成 / 补齐示例商品（幂等）
php think demo:products --reset    # 先删后建（重建示例）
php think demo:products --purge    # 仅清除全部【示例】商品及自动创建的示例商户（不生成）
php think demo:products --aid=1    # 指定平台租户 ID（默认 1）
```

## 正式上线不想保留示例数据

任选其一：

1. `php think demo:products --purge`（推荐，只删示例、不动真实数据）；
2. 后台按「【示例】」前缀搜索后删除；
3. `php think migrate:rollback` 回滚该种子迁移——只删【示例】商品与**自动创建**的同名示例商户，真实商户（如「义务包包」）及其数据一律保留。
   > 注意：若该迁移之后又新增过别的迁移，`rollback` 默认只回滚最后一个迁移，此时请改用方式 1 或 2。


## 商户文章示例（demo:articles）

「商户 → 文章列表」按点大口径是 **bid>0 的商户自建文章**（点大由商户登录商户后台 Backstage 创建，分类也归属商户 `article_category.bid=商户ID`）；本项目暂无商户端入口，故用同一保存口径补齐演示文章。

- 复用第一个正常商户（当前库为 bid=7「义务包包」），先建 2 个商户文章分类（【示例】门店动态、【示例】优惠活动），再生成 4 篇【示例】文章，封面在 `public/uploads/demo/article_m_*.jpg`（600×430）。
- 经 `ArticleService::save` 真实落库（内容为页面设计器 richtext JSON，与商品详情装修同源），`status=1`。
- 迁移 `20260919120001_seed_demo_articles` 会在 `migrate:run` 时幂等生成；也可手动执行：

```bash
php think demo:articles            # 生成 / 补齐商户示例文章（幂等）
php think demo:articles --reset    # 先删后建
php think demo:articles --purge    # 仅清除【示例】文章与示例分类（不碰真实数据）
php think demo:articles --aid=1    # 指定平台租户 ID（默认 1）
```

平台文章（bid=0）在「扩展 → 文章管理 → 文章列表」由平台自行「添加」，不属于本演示数据。

## 商户短视频示例（demo:shortvideos）

「商户 → 短视频列表」按点大口径是 **bid>0 的商户自建短视频**（点大由商户登录商户后台 Backstage 创建，分类也归属商户 `shortvideo_category.bid=商户ID`，短视频分类为平铺一级、无二级）；本项目暂无商户端入口，故用同一保存口径补齐演示视频。

- 复用第一个正常商户（当前库为 bid=7「义务包包」），先建 2 个商户短视频分类（【示例】商户视频、【示例】好物推荐），再生成 3 条【示例】短视频。
- 封面为 GD 生成的 350×500 竖版图 `public/uploads/demo/shortvideo_m_*.jpg`；视频为随库提交的 `shortvideo_m_1~3.mp4`（约 0.8MB/个的公共样片，本地资源、不依赖外链；若线上文件缺失会尝试由 `shortvideo_demo.mp4` 复制或回退公共样片地址）。
- 经 `ShortvideoService::videoSave` 真实落库（名称/简介/分类/封面/视频/播放点赞数/序号/评论开关等字段齐全）；`business_sysset.shortvideo_check=0` 为免审，示例直接 `status=1`（已通过）。
- 生成前会把历史平台短视频与分类中 `bid IS NULL` 的存量**规范化为 0**，使平台「营销 → 短视频 → 视频列表」（固定 bid=0）仍能看到原平台视频，与商户视频严格隔离。
- 迁移 `20260919130001_seed_demo_shortvideos` 会在 `migrate:run` 时幂等生成；也可手动执行：

```bash
php think demo:shortvideos            # 生成 / 补齐商户示例短视频（幂等）
php think demo:shortvideos --reset    # 先删后建
php think demo:shortvideos --purge    # 仅清除【示例】短视频与示例分类（不碰真实数据）
php think demo:shortvideos --aid=1    # 指定平台租户 ID（默认 1）
```

平台短视频（bid=0）在「营销 → 短视频 → 视频列表」由平台自行「添加」，不属于本演示数据。

## 说明

示例数据仅用于演示与验收，可随时安全删除，不影响任何业务表结构与真实数据。
